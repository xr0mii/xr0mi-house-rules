# Выпуск на GitHub

Проект подготовлен для `xr0mii/xr0mi-house-rules`. Если адрес изменится, исправьте URL в `module.json` и README перед публикацией.

## Первый выпуск

1. Создайте репозиторий `xr0mi-house-rules` в аккаунте `xr0mii`. Для установки без авторизации он должен быть публичным.
2. Загрузите всё содержимое этой папки, включая `.github`, в корень репозитория. Не загружайте `dist` и архив исходников внутрь проекта. README, `module.json` и `package.json` должны быть в корне.
3. Убедитесь, что workflow **Checks** завершился успешно.
4. Создайте и отправьте тег **v0.4.1**. Workflow **Draft release** проверит проект и создаст черновик с тремя файлами.
5. Проверьте черновик, проведите ручные проверки из TESTING.md. Затем опубликуйте релиз как обычный выпуск, отметив его последним (**latest**). До этого ссылка `releases/latest` работать не будет.
6. Проверьте установку по Manifest URL из README в отдельной установке или тестовом окружении Foundry.

Не создавайте вручную опубликованный релиз до завершения workflow: он должен сначала создать черновик с готовыми файлами.

## Последующие выпуски

Измените версии в `module.json` и `package.json`, обновите версию в `download`, CHANGELOG и docs/RELEASE_NOTES.md. Запустите проверки и сборку. После отправки нового тега workflow снова создаст черновик; проверьте и опубликуйте его.

Манифест релиза ссылается на ZIP конкретного тега. Поле `manifest` указывает на манифест последнего опубликованного релиза. Так обновления не смешивают код разных версий.

## Если workflow нужно повторить

Если черновик уже существует, удалите только этот черновик в интерфейсе GitHub, затем повторите workflow. Опубликованные релизы и теги автоматически не перезаписываются.
